# BlindPreflight 能力边界

BlindPreflight 是**自检辅助**，不是合规证明。“没有发现”不等于“已经匿名”。提交前请对照会场官方政策人工复核。

## 一、隐私模型

### 承诺

| 承诺 | 如何保证 |
|---|---|
| 稿件不上传 | 应用代码中没有 `fetch` / XHR / WebSocket / `sendBeacon` / 表单提交（ESLint 强制）；唯一的网络读取是同源的示例 PDF |
| 不加载第三方资源 | CSP：`default-src 'self'`、`connect-src 'self'`、`form-action 'none'`、`frame-src 'none'`；pdf.js 的 worker、cmaps、字体、wasm 都打包在本站 |
| 只在内存中处理 | 文件、正文、发现、复核决定都只在页面内存里；“清除全部”会销毁 pdf.js 文档并清空状态，关闭标签页即消失 |
| 本地存储只放偏好 | localStorage 只记录所选会场预设、亮 / 暗主题和自定义预设的规则设置，不含文件名、正文、自定义词或结果 |
| 不访问稿件里的链接 | 链接只做字符串解析；点击报告中的网址需要二次确认，只允许 http(s)，并带 `noopener noreferrer` |
| 渲染安全 | 不使用 `v-html`；稿件文字一律纯文本显示，双向控制字符（如 U+202E）显示为 `⟨U+202E⟩` |

E2E 测试会拦截一切非本机请求，并断言整个流程中外部请求数和非 GET 请求数为 0。

### 报告导出

- 默认**证据脱敏**：姓名、邮箱、机构、个人或机构主页的主机名都会打码；GitHub、Hugging Face、arXiv、匿名托管等公共平台的主机名保留，方便定位。
- 默认**隐藏文件名**：文档显示为“主稿 / 补充材料 n”，报告文件名只含时间戳。
- 报告不包含 PDF 字节、整页文字或自定义词清单（只记录词的数量）。
- HTML 报告不含脚本与可点击链接，自带禁止外部资源的 CSP 和 `no-referrer`。
- 关闭脱敏后，报告**会包含原文身份信息**。导出前界面会给出提示，请谨慎转发。

### 清理版 PDF

- 只删除元数据（Info、XMP、PieceInfo）、审阅批注（保留文内链接与表单域）、嵌入附件，以及可选的外部链接目标和标题；**不修改正文内容流**，作者区、邮箱、致谢等仍需改源文件。
- 保存前会回收文件中不可达的对象（含增量更新残留），被删除的内容不会留在新文件的字节里。
- 清理版下载名固定为 `paper.pdf` / `supplement-n.pdf`；清理和复检都在本机完成。
- 会去掉 JPEG 图片的 EXIF / IPTC / XMP 与注释段（保留 JFIF、ICC 颜色配置和 Adobe 颜色信息），并把增量保存合并为单一版本。
- 不处理字体名、隐藏图层、非 JPEG 图片内嵌的元数据和页面内容里的文字。

### 会话中记住的作者名

- 从元数据里得到的作者名，会在本次会话后续的检查（清理版复检、上传的新版本）中继续用于查找正文，并在说明中标注“上一版”。这样删掉元数据后，正文里的作者名不会被误判为“已修复”。
- 这些名字只在页面内存中，“清除全部”或关闭标签页即消失，不写入报告或 localStorage。

### 承诺之外

- 浏览器扩展、操作系统、杀毒软件等能读取页面内存的程序不在保护范围内。
- 如果你从不可信的站点打开 BlindPreflight，上述承诺无法成立。请使用自己构建或可信来源部署的版本。
- 浏览器自身可能把下载的报告写入下载历史。

## 二、输入范围

- 只支持 PDF。主稿 1 份，补充材料至多 2 份。
- 单个文件最大 25 MB，合计最大 50 MB；每份最多 100 页，合计最多 200 页。
- 加密、损坏或伪装成 PDF 的文件会被拒绝，并显示原因。
- 不支持 LaTeX 源码、Word、zip 压缩包、代码仓库或补充视频。

## 三、检测方式

全部是**确定性规则**：正则、词表、版面启发式，没有机器学习和云端模型。

- 文本来自 pdf.js 的文字层，并做 Unicode 规范化（全角转半角、连字拆分、零宽字符、软连字符）。为跨行和断词另做多视图匹配。
- 版面区域是启发式判定：首页作者区、页眉页脚带、致谢、参考文献、附录。区域只影响严重度和说明，**不会因此丢弃命中**。
- 每条发现都给出页码、bbox、置信度、原因和修改建议；元数据、附件这类无坐标的发现会标注字段名。
- 会场预设只调整严重度、致谢政策和审稿模板标记，不会新增或删除会场没有要求的检查。审稿模板标记找不到时只给“需核实”，因为会场可能调整模板文字。
- 自定义预设由你自己定义，条款没有经过核验；报告中会注明。

## 四、不能检测的内容

| 类别 | 说明 |
|---|---|
| 图片中的文字 | 没有 OCR：图表、截图、扫描页、Logo 里的姓名和机构都查不到。文字过少的页会在“覆盖情况”中列出 |
| 图片元数据 | 检查 JPEG 的 EXIF / IPTC / XMP、图片自带的 XMP 与 JPEG 2000 中的 XMP；不解析 PNG 等其他格式的内嵌元数据 |
| 字体与对象层面 | 检查字体名；不检查字体文件内部的版权 / 设计者字段 |
| 增量保存的旧版本 | 检查旧版本的 Info 与 XMP（最多 5 个旧版本），旧版本里的作者名也会用于查找正文；不检查旧版本的正文与批注 |
| 链接目标的内容 | 不访问网址，因此无法判断匿名仓库里的 README、提交记录、LICENSE 是否泄露身份 |
| 第三人称自引 | 能抓到“our previous work”这类第一人称写法，但不能判断第三人称自引是否“过多”或“过于明显” |
| 内容推断 | 研究主题、独有数据集、写作风格、实验设备带来的“可推断身份”需要人工判断 |
| 未知姓名 | 不知道作者是谁。姓名只能来自元数据、作者区模式或你填写的自定义词，**建议填写全部作者名和系统名** |
| 白字 / 隐藏文字 | 隐藏文字只要在文字层中就会被检查，但不会特别标注“隐藏” |
| 非中英文 | 规则只覆盖中文和英文 |

## 五、误报与复核

- 第三方公开库（如 `github.com/pytorch/pytorch`）、参考文献条目里的作者和机构、示例域名（`example.com`）会降级或只给提示。
- 每条发现都可以标记为：已修复、引用他人、第三方、会场要求、无关。复核决定只在本次会话中有效。导出时可以选择是否包含已忽略的发现，但汇总数字始终保留。
- 换了文件重新扫描后，会与上一版按“文件 + 规则 + 命中内容”对比：忽略类决定沿用到仍存在的发现，“已修改”却仍存在的恢复为待处理，其余决定清空。
- 人工核对清单的勾选只在本次会话中有效；导出时可选择写入报告（只写条目和是否勾选）。

## 六、会场预设状态

条款核验日期为 2026-11-09。会场可能随时更新政策，以官方页面为准。

| 预设 | 实现状态 | 差异 |
|---|---|---|
| 通用双盲 | 已实现 | 基线 |
| ARR | 已实现 | 致谢只允许 AI 使用声明 |
| NeurIPS 2026 | 已实现 | 投稿版禁止致谢；资助信息升为高危 |
| ICLR 2026 | 已实现 | 致谢中不得含身份信息 |
| MobiCom 2026 | 部分实现 | 所有内嵌超链接都提示复核 |
| CVPR 2026、USENIX Security 2026、CCS 2026 | 仅参考 | 显示条款摘要，检查按通用规则执行 |
