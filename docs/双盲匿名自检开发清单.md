## 01｜我的判断：能做，但不能再宣传成无人做过

> **建议做成“有证据定位的投稿匿名预检”，不是“一键匿名化”或“保证通过”。** 已有本地身份扫描器，也有本地 PDF 元数据清理器。值得打磨的是 PDF 正文与真实链接的联合定位、会场政策差异、中英规则、明确的覆盖不足，以及可以复核的报告。


- [ ] 暂定名称：盲审前哨 / BlindPreflight；先查名称是否撞商标，不在三周里投入品牌系统。
- [ ] 一句话介绍：论文不上传，在浏览器里查出可能暴露作者的文件信息、原文和链接，按页定位并解释如何复核。
- [ ] 核心闭环：选择会场 → 放入审稿版 PDF → 可选填写自己的身份词 → 查看证据 → 回源码修改 → 导出新 PDF 重新检查。
- [ ] 面向作者保护自己的匿名性，不帮助评审追踪作者，不联网搜索论文、作者、机构或 GitHub 身份。
- [ ] 价值重点排序：真实问题与可用性 > 演示闭环 > 设计细节 > 有记录的 Qoder 辅助开发；不为了复杂度硬塞大模型/OCR/后端。
- [ ] 约束写进 PRD：Qoder AI IDE 完成主要开发，Qoder Sites 承载部署；纯静态前端、无论文上传接口、无账号依赖、无运行时云模型。
- [ ] 本 Page 的方框是截至 2026/11/09（日本时间）记录的待办，不是已实现功能，也不是可直接点击保存进度的工具；实施时复制到你自己的开发任务系统。

## 03｜用户、场景与成功标准

- [ ] 首要用户：首次双盲投稿的本科生/研究生；第二用户：课题组投稿前负责检查的同学；第三用户：导师快速复核匿名稿。
- [ ] 场景 A：作者已删首页名字，但 PDF Author 仍是真名；报告显示文档级字段，不强行跳第一页。
- [ ] 场景 B：正文只写 Code，但内嵌链接是实名仓库；显示可见文字、真实 URL 和可点击区域。
- [ ] 场景 C：复制旧模板的致谢、资金号、页眉姓名没有删；按页定位，解释政策与误报可能。
- [ ] 场景 D：审稿版正文正常，supplement.pdf / main.tex / 图像文件名泄露；报告明确主稿与补充材料的各自覆盖。
- [ ] 场景 E：正文提及他人机构/开源项目/作者姓名；用户可标为合法引用，不能被工具逼着删除科学引用。
- [ ] 非目标：审稿人对陌生稿件识别作者；出版社批量处理；法律/合规背书；格式、参考文献质量、学术原创性评价。
- [ ] 产品成功标准：合成的直接身份泄露集合不漏检；能解释每条命中；无文件内容上传；不把解析失败当零风险；主要操作新用户可在 3 分钟内完成。
- [ ] 性能目标先作为待测门槛：20 页、10 MB 以内文本型 PDF 在普通笔记本热启动 10 秒内完成；取消在 1 秒内有可见反馈。未达标就实事求是写实测值与优化计划。

## 05｜纯前端架构与选型理由

#### 架构流程

- **input｜本地 File / ArrayBuffer**：PDF + 可选 .tex；不构造上传请求
- **pdf｜PDF.js worker + 抽取适配层**：Info/XMP、文本项、页坐标、链接/批注
- **normalize｜文本规范化与来源映射**：分栏、去断行、保留原句与 bbox
- **engine｜纯函数规则引擎**：规则版本 + 会场预设 + 可选身份词
- **review｜本地结果与人工复核**：列表/PDF 定位；覆盖不足单独展示
- **export｜本地报告下载**：JSON / HTML 打印；回源码修改后复查

连线：
- input → pdf
- pdf → normalize
- normalize → engine
- engine → review
- review → export


| 技术 | 建议 | 理由与边界 |
| --- | --- | --- |
| Vite + React + TypeScript | 推荐这一套；熟 Vue 可等价替换 | 静态产物简单；strict 模型契约适合静态扫描思路。不同时引两个框架。 |
| pdfjs-dist / PDF.js | 必需；包和 worker 锁同一版本 | 负责渲染、文本、公开元数据与批注；worker 同源打包，不使用外部 CDN。 |
| pdf-lib | 按需引入 | 合成测试元数据/附加文件，或 P2 清理副本；不是全文抽取器，MVP 不用它重写用户稿。 |
| Web Worker | PDF.js 自带 worker + 规则 worker 按性能决定 | 先复用 pdf.js 抽取，把耗时规则/ZIP 移 worker；不是强隔离沙箱或防恶意文件的保证。 |
| JSZip / 可选 exifr | P1 ZIP / P2 原图元数据 | 只读不执行；JSZip 不天然防 zip bomb，完成严格资源评估前不开 ZIP。 |
| Vitest + Testing Library + Playwright | 单测/组件/E2E | 规则与 UI 分离，能验证坐标、取消、导出和网络约束。 |
| CSS / 轻量组件库 | 只选一种 | 重视排版、焦点与状态一致性；无需复杂设计系统或动画依赖。 |
| 存储与服务 | 内存为默认；设置可单独 localStorage | 不存论文原文、姓名/邮箱、文件名和报告到持久存储；不需要 Supabase/数据库/云函数。 |



- [ ] 锁定依赖版本与 lockfile；正式实现以安装版本的类型声明/API 为准，不照抄 draft API 的新增方法。[S17]
- [ ] Vite 构建 worker、cMaps、standard_fonts、WASM 等依赖按选用版本实际需要一并同源部署；不能只复制 pdf.worker 文件便认定所有字体都离线。
- [ ] 页面无远程字体、远程图标、外链脚本、运行时 LLM API；示例文件与规则 JSON 都随构建静态提供。
- [ ] 应用不在 URL query/hash、document title、日志、analytics 事件里拼入文件名、论文题名、邮箱或正文。

## 08｜PDF 抽取：这部分决定可信度

- [ ] File.arrayBuffer() 后验证 PDF 文件头与 parser 结果；accept=.pdf 只是 UI 提示，不是安全校验。文件 MIME 为空或扩展名大小写变化要正常处理。
- [ ] PDF.js getDocument 使用本地 data，不传用户链接；读取 getMetadata、逐页 getTextContent、getAnnotations、附件清单；只用锁定版本公开 API。
- [ ] 保留原始 TextItem 与 transform；行聚类先按相近基线和字号，再按 x 排序；不能把 items.map(str).join(' ') 当可靠的全文阅读顺序。
- [ ] 双栏：按 x 分布和页面布局切块，单栏标题/跨栏图注单独处理；行列不确定时降低文本上下文置信度，仍做单项邮箱/姓名匹配。
- [ ] 连字/Unicode：处理 ﬁ→fi、ﬂ→fl、NBSP、soft hyphen、全角符号、零宽字符与 NFC/NFKC 策略；保留原句，不用规范化字符串直接显示替代原文。
- [ ] 断词：仅在同栏相邻行、上一行末尾字母+连字符且下一行字母时生成合并候选；真实带连字符的姓名/术语不能盲目合并。原始视图与合并视图均可匹配后去重。
- [ ] 中英文断句：结合 。！？、英文句号/问号、缩写和换行；URL、邮箱、e.g.、et al. 不能随便断裂；证据片段最多约 240 字，可展开上下文。
- [ ] 映射：每个规范化字符保留原始 TextItem index / offset；命中跨两行生成两个 bbox；若字体宽度不可精确分字，标“近似整词/整行高亮”，不要假精确。
- [ ] 坐标测试：页面 rotate=0/90/180/270、CropBox、不同 page size、缩放、DPR=1/2 都要验证 overlay 与画面同位。
- [ ] 参考文献/附录/致谢区域用标题与版面启发式标记，识别不确定时不静默屏蔽；引用区也可能有真泄露，必须仍可展开检查。
- [ ] 扫描版：每页少于约 20 个可见字符或异常字形比例高时标“文本不足/可能扫描页”，不是“匿名通过”。阈值先测合成页，可按图片/公式密集页区分。
- [ ] OCR 不在 P0；可让用户回原文导出文本 PDF 或进行本地 OCR 后重试，保留“原版图像内容未检查”提示。云 OCR 与隐私承诺冲突，不作为隐式 fallback。
- [ ] 部分页抽取失败时报告已处理页/失败页；损坏、密码保护、异常字体、ToUnicode 缺失都提供明确诊断。MVP 不收集密码，只提示用本地受信工具导出可读副本。
- [ ] 图片内人名、校徽、照片、截图账户名、公式字形、隐藏层/历史增量对象无法全面保证；扫描覆盖表把这些列为人工复核。
- [ ] 渲染按当前页和相邻页懒加载；取消 RenderTask 后再 cleanup/destroy，释放 canvas/worker/Blob URL；不要每次缩放把全稿重新渲染。
- [ ] 不要为了验证链接偷偷联网，或为拿图片在后台访问图像地址；全文抽取过程只处理文件本身。



## 09｜检测规则目录：入口、启发式、误报与建议

以下正则是 JavaScript/TypeScript 的规则入口草案，不是完整语义判定器；实施时写成测试覆盖的独立规则。P0/P1/P2 表示开发优先级，不等于 Finding 的风险等级。



### R01｜PDF Info / XMP 身份字段｜P0

结构化读取，不用二进制正则：info.Author、Title、Subject、Keywords、Creator、Producer，以及 XMP 的 dc:creator、dc:title、pdf:Author、xmp:CreatorTool 等。


- [ ] Author 非空且不是明确匿名占位符时，输出高优先级候选；匹配用户填写的作者全名时提升置信度。Author=Anonymous / Anonymous Authors 不按真名处理。
- [ ] Title 与正文题名相同不是泄露；Creator=LaTeX、Producer=pdfTeX 仅作信息展示。只有字段含个人名、邮箱、本地用户路径或具体实验室/机构时才升级。
- [ ] Info 和 XMP 分开检查、分别展示，二者不一致也记录；XMP 缺失不是解析失败。不能读到的自定义字段标记覆盖不足，不宣称扫描了所有隐藏元数据。
- [ ] 位置写“文档级 → Info.Author / XMP.dc:creator”，page=null、bbox=null；建议回源码清理后重新导出，不把该项伪装成第一页文本。




### R02｜标准邮箱 / mailto｜P0

/[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}/giu


- [ ] 同扫正文、元数据、批注和超链接目标；支持 mailto:，先按 URL 解析再匹配。每个邮箱保留原句和源位置。
- [ ] 第一页/作者块/页眉页脚中的邮箱优先级高；参考文献、公开数据集维护者邮箱默认中或低，不能一见邮箱就判定为作者本人。
- [ ] example.com、example.org、example.net 及明显匿名占位邮箱降为信息，不从报告中彻底消失；obfuscated 的 name [at] domain [dot] edu 另设 P1 规则。




### R03｜个人姓名与机构自定义词｜P0

用户词条先作 Unicode 规范化与正则转义；英文按 Unicode 字母/数字边界精确匹配，中文按完整词条匹配，不把词条直接拼进 RegExp。


- [ ] 允许可选输入：中文全名、英文全名与别名、共同作者、机构、实验室、Git 用户名；每行一项，默认内存保存。完全不填写也能运行通用规则。
- [ ] 2 字母英文缩写、单个姓氏、长度很短的中文词提示歧义，默认不自动提升高风险；用户可明确打开“严格匹配短词”。
- [ ] 同一姓名出现在参考文献作者列表不等于违规；引用区低优先级，作者块/页眉页脚/元数据命中则高。报告明确写“匹配了你提供的词”，不是算法推断身份。




### R04｜学校 / 机构提示词｜P0

/\b(?:university|institute|institution|department|laboratory|college|school of|research center|research centre)\b|(?:大学|学院|研究所|实验室|研究院|附属医院)/giu


- [ ] 只在第一页作者块、致谢、资金、页眉页脚等区域优先运行；正文全局命中仅作低置信候选。要截取相邻 60–120 字，不把单个 University 当机构名。
- [ ] 通用 institution、university students、Stanford Cars 数据集、他人论文机构、研究对象的学校都可能合法；按上下文降级，可标记“数据集/研究对象/引用他人”。
- [ ] 不做庞大的全球大学词库或远程实体识别；可内置一小份有许可证的示例词，用户自定义词优先。




### R05｜致谢章节｜P0

/^\s*(?:\d+(?:\.\d+)*[.)]?\s*)?(?:acknowledg(?:e)?ments?|致\s*谢)\s*[:：]?\s*$/gimu


- [ ] 在重建行上匹配标题，结合字号/独立一行识别章节；截取至下一同级标题，最多 2,000 字或跨 2 页，超过范围提示截断。
- [ ] 正文中的“we acknowledge a limitation”不当章节；References 中含 Acknowledgments 的论文标题不当本稿致谢。识别“致 谢”、Acknowledgements 两种拼写。
- [ ] ARR 当前允许仅含生成式 AI 披露的致谢；CCS 有 AI 使用披露要求，不能让一刀切删除致谢破坏必要声明。含人名、资助、机构时再提升并引用所选政策。




### R06｜资金 / 项目编号｜P0

/\b(?:grant|award|project)\s*(?:no\.?|nos\.?|number|#)?\s*[:：]?\s*[A-Z0-9][A-Z0-9./-]{3,39}\b/giu；/\b(?:NSF|NSFC|NIH|ERC)\b|国家自然科学基金|资助|基金号|项目编号/giu


- [ ] 关键词与编号在同句或相距 100 字以内才构成资金候选；合并两条规则的同一发现。自然科学基金编号并非只有一种固定长度，不写死“八位数字必然基金号”。
- [ ] DOI、年份、页码、算法编号、benchmark award 不是资助；编号只有全数字但无资助语境时不报高风险。
- [ ] 明确建议“按会场要求匿名化资金来源或移至非审稿材料”，不建议永久删除应披露的资助信息；伦理审批编号也可能重要，单独人工核实。




### R07｜GitHub / GitLab / Hugging Face / 主页｜P0

/https?:\/\/[^\s<>"{}]+/giu；之后用 URL 解析 host、path；github.com/<owner>/<repo>、gitlab.com/<namespace>/...、huggingface.co/<owner>/...、<user>.github.io


- [ ] 合并可见文本 URL、PDF Link annotation 的真实目标、LaTeX href/url 内容；删掉句尾标点要保留平衡括号，不只靠这条正则吃完整 URL。
- [ ] 本稿语境 our code / our implementation / code is available / 我们的代码 / 本文代码 且链接非匿名，报高优先级；仅见 owner 的常规第三方库如 pytorch/pytorch、引用其他项目，默认人工核实。
- [ ] 用户自定义用户名与 host/path 命中时升级；GitLab 支持多级 group，不假定首段必然个人。Hugging Face 的 models/datasets/spaces 路径要分别解析。
- [ ] 给出 anonymous.4open.science 作为可选办法而非自动重写；即使其域名匿名，也提示 PDF/图片不自动脱敏、外链与过期设置需复核，不给“已安全”认证。[S24]




### R08｜第一人称自引措辞｜P0

/\b(?:our\s+(?:previous|prior|earlier)\s+(?:work|paper|study|studies)|we\s+(?:previously|earlier)\s+(?:proposed|showed|presented|introduced|demonstrated))\b/giu；/(?:我们|本团队|本课题组|笔者|作者)(?:此前|先前|之前|早期|前期|曾经|曾)(?:.{0,16})(?:提出|研究|工作|证明|发现|发表)/gu


- [ ] 检查同句或前后 100 字是否有 [12]、[3–5]、作者年份引用；有自引措辞+引用才提高置信度。无引用只提示，不断言引用对应作者本人。
- [ ] 新增中文模式“在我们先前的工作中”“我们的前期研究”；our method / we propose / our work 本身是正常叙述，不触发该规则。
- [ ] third-person 的 Smith et al. [12] 不能自动当泄露；也不要建议把所有 self-citation 删掉或统一写 Anonymous，政策往往要求正常第三人称引用。给出语义保持的示例改法并让作者自行确认。




### R09｜隐式第一人称身份｜P1

/\b(?:our\s+(?:lab(?:oratory)?|university|institution)|at\s+our\s+(?:department|university))\b/giu；/(?:本校|我校|本实验室|我们所在的|我院|本院)/gu


- [ ] 仅报中/低置信：our lab 可不具体识别学校，研究设置也可能必须保留。结合具体校名、地址、项目名再升级。
- [ ] 不扫描互联网推断学校、不做论文去匿名化；规则只帮助作者发现自己文件内的可疑表述。




### R10｜所有内嵌超链接 / 身份与规则差异｜P0

逐页 getAnnotations()，仅收集 Link 的 url/unsafeUrl、rect、dest；仅做字符串检查，不执行 action、不访问链接。内部跳转 dest 与外链分开。


- [ ] 页面只显示“代码”也可能链接 github.com/real-name/repo；报告必须展示真实目标与可见文本差异。mailto 与机构主页也检查。
- [ ] 不把 DOI、arXiv 引用、第三方 benchmark 链接一律当违规。CVPR 2026 是禁止扩展贡献内容/规避评审的外链，不是禁止任何参考链接。[S13]
- [ ] MobiCom 2026 格式条款写 PDF 不得含 embedded hyperlinks，而匿名条款又允许匿名补充材料链接；记录为“可见网址与可点击链接有区别，但官方未在此明确解释”，严谨提示人工核对，不能假装已消除歧义。[S14]
- [ ] 来源 URL 在报告中默认纯文本；只有用户主动选择“打开外链”才在确认后以 noopener/noreferrer 打开 http(s)，不生成可执行 javascript: 或 file: 链接。




### R11｜页眉 / 页脚残留姓名｜P0

页面上/下各 10% 区域的文本，规范化后在至少 2 页重复，且重复页占可比页面的 50% 以上；再结合姓名词、邮箱、机构词判断。


- [ ] 区域阈值属于可调启发式，按页面旋转后的坐标检测；短稿不足两页仍检测显式邮箱/自定义姓名，不使用重复判据。
- [ ] “Anonymous submission”“Under review”“Paper ID 1234”、页码、论文标题默认不是泄露；只有 running title 含作者信息才报。
- [ ] 同一作者名多页重复可聚合为一个发现，列出所有页码，默认只展示 3 段证据，可展开全部。




### R12｜文件名 / 补充材料路径｜P0

/(?:author|camera[-_ ]?ready|final|姓名|作者|终稿)/giu；以及自定义姓名/机构/用户名词条匹配文件名与 ZIP entry


- [ ] final 本身不代表泄露，只信息提示；zhang-final.pdf 若没配置姓名词，仅弱候选，不伪造姓名识别。document-level 显示文件名，不显示为正文页码。
- [ ] 主 PDF、补充 PDF、附件、源码路径都检查；个人 home 路径、作者命名图片仅在本地分析；缺失的补充材料列为“未提供/未检查”，不能算已通过。




### R13｜PDF 批注 / 评论作者 / 表单残留｜P0 基础、P1 深入

逐页 annotations 读取锁定 PDF.js 版本公开提供的 title/titleObj、contents/contentsObj、subtype、rect；字段有版本差异，需要适配层。


- [ ] 存在批注先列人工核实项；批注 author/title 命中姓名、邮箱或机构时升高；高亮/删除线视觉标记不等于 Word 修订历史已完整恢复。
- [ ] TODO、FIXME、XXX、TK、待补充、作者回复、删除此处作为编辑残留低优先级提示；不得把正常包含 TODO 的计算机代码当匿名性直接证据。
- [ ] 明确 PDF 通常不包含 DOCX 的完整 Track Changes 历史；仅检查可提取批注、删除线与可见修订残留。不支持源 Word 检查，不宣称清除了所有修订记录。




### R14｜LaTeX 身份 / 评论 / 构建路径｜P1

/\\(?:author|affiliation|institute|email|thanks|orcid|pdfinfo)\b/gu；/\\hypersetup\s*\{/gu；/\\(?:added|deleted|replaced|todo)\b/gu；/%[^\r\n]*/gu 仅作词法入口


- [ ] 先实现 .tex 文本；用轻量词法扫描器处理平衡花括号、转义百分号、注释、verbatim 和注释环境，不能用单条正则假装能完整解析 TeX。
- [ ] 区分有效输出与未编译源码：\author{Real Name} 在匿名模板里可能被隐藏，PDF 未泄露但源码若一并提交仍有风险；finding 标为“源码可识别信息”，不要说 PDF 一定泄露。
- [ ] \hypersetup 的 pdfauthor/pdfcreator、\pdfinfo 的 Author、acmart 的匿名选项、模板 final/review 开关分别给提示；不自动改模板，不编译/执行 TeX。
- [ ] 源码的每条发现给相对路径、1 起始行号和原句，不伪造 PDF 页码；bib 中其他人姓名默认引用，不自动认成作者本人。




### R15｜ORCID / 本地用户路径 / 签名｜P1

/\b\d{4}-\d{4}-\d{4}-\d{3}[\dX]\b/giu；/(?:[A-Z]:\\Users\\[^\\\r\n]+|\/(?:Users|home)\/[^\/\s]+)/giu


- [ ] ORCID-like 命中后可做校验位验证，未校验称“疑似 ORCID”；链接的 orcid.org 路径也扫描。作者块 ORCID 高优先级，参考资料中的他人 ORCID 人工核实。
- [ ] 只识别文件实际带的路径，不读取本机路径/用户名。PDF 数字签名若锁定版本有稳定公开读取接口再支持，否则标未检查，不能臆造字段。




### R16｜图像 EXIF / XMP｜P2，先不列发布必备

仅对源码 ZIP 中原始 JPEG/PNG 等可直接读取的图片使用本地元数据解析库；PDF 内图像流不保证保留 EXIF，解码到 canvas 后通常已没有原始元数据。


- [ ] 原始图像 Artist、Copyright、UserComment、GPS 等可提取才显示字段和值；不能提取写“未检查/格式不支持”，不能显示“未发现所以无 EXIF”。
- [ ] pdf.js operator list / 私有对象不是稳定通用原图导出 API；三周版本不为此写 PDF 解码器。PDF 图内肉眼姓名、校徽、实验室水印保留人工检查项。
- [ ] 此项若延期，产品能力表与 README 同步写清楚，不把 EXIF 按已扫描类型计入覆盖率。




### R17｜附加文件与补充材料泄露｜P0 清点、P1 内容

getAttachments() 的返回形态按版本适配；列出附件名/类型/大小。补充 PDF 走同一条检测管线，不自动打开任意附件。


- [ ] P0 支持主稿+最多 2 份补充 PDF 的独立分析与汇总，顺序处理、按 documentId 隔离页码；不把补充第 2 页当主稿第 2 页。
- [ ] 嵌入附件先清点与文件名检查；P1 仅对用户选择的受支持 PDF/.tex 做深扫，其他二进制/视频/压缩包显示未检查，禁止自动运行或渲染 HTML/SVG。
- [ ] 导出最终人工清单：视频片尾、音轨口播、截图账户名、代码 LICENSE/README/.git、Notebook 输出、数据下载页、问卷机构名；这些没有文件就不能被工具认证。




## 10｜风险等级、置信度、去重与误报处理

- [ ] severity 是处理优先级，confidence 是命中解释可信度，两者独立；不显示“99% 是作者姓名”这种未经校准的概率。
- [ ] high：明确非匿名 Author、用户全名在作者块/页眉、本人邮箱、实名本稿仓库、含作者标识的批注。没有作者词时只称“疑似身份信息”，不推断真实归属。
- [ ] medium：第一人称自引+引用、疑似基金号、正文机构、个人主页、需要结合会场判断的外链。info：通用生成软件、日期、final 文件名、无具体标识的章节词。
- [ ] 按规则→上下文→位置→预设进行透明分级；同时保留所有触发理由。不用总分 0–100 伪装科学性，不用“满分即通过”。
- [ ] 相同 evidence span 上多个规则命中合并成一条，保留所有 ruleIds；URL 可见文字与 annotation 指向相同目标时合并来源，page/bbox 不丢失。
- [ ] 用户操作：标“是他人的引用”“公开第三方项目”“必须保留的伦理信息”“不相关”“待确认”；可撤销。忽略不从原始扫描记录中抹去。
- [ ] 某条会场规则关闭后显示“此检查未启用”，不要把关闭产生的零结果称通过；规则预设切换重新计算发现与解释，人工判断按可追溯标识保留或提示失效。
- [ ] 负例必须常驻测试：We propose、our method、Smith et al.、参考文献中的机构、公共 GitHub 库、DOI/arXiv、Anonymous Authors、AI 使用披露。
- [ ] 所有修复建议只提供动作和示例，不自动重写论文；删引用、删伦理声明、删资助披露之前必须让作者看政策。

| CVPR 2026 [S13] | 禁止身份致谢与身份链接；禁止扩展内容或规避审稿的外链；允许不属本稿贡献的部分引用链接 | 链接规则只能人工判断贡献归属；不是“所有外链必违规”。 |

| USENIX Security 2026 [S15] | 匿名标题页/图/附录；第三人称自引；罕见匿名引用需批准；artifact 与链接匿名，必须有伦理/Open Science 信息 | 只查身份风险，不把伦理/Open Science 章节本身当应删除内容。 |
| ACM CCS 2026 [S16] | 实名仓库/资金/第一人称自引不可泄露；匿名 artifact 网址直接写论文；不许可追踪/自管理动态站点；AI 披露另有要求 | 只实现可从文件判断的部分；不能离线认证网站无追踪、不可更新、期限足够。 |



- [ ] 每个预设记录 venue+year+track+submissionPhase；不能只写“NeurIPS 模式”便让未来年份继续默认有效。
- [ ] 配置存来源 URL、章节、小段证据摘录、verifiedAt=2026-11-09、维护人、verificationStatus；未经二次核对的条款标 unverified，不能默认严格执行。
- [ ] 把“官方条款已看过”“检测逻辑已实现”“通过测试”做三种不同状态；资料已核验绝不代表产品已支持。
- [ ] 将 policy observation 与 rule verdict 分开：比如“该页含外链”可确定，“外链扩展贡献”通常要用户判断；报告显示两层。
- [ ] 明确允许投稿前预印本的政策不等于可以把实名预印本当本稿链接直接暴露身份；不做全网 preprint 检查。
- [ ] 按官方新版本更新时保留旧 presetSnapshot，历史报告不被新规则静默改写；离线没有自动更新承诺。
- [ ] 发布前再核验一遍官方页面，尤其 ARR 的动态政策；没有时间核验就标“参考预设，请核对当前条款”，而不是偷偷泛化。



## 12｜页面、组件、状态与交互细节

- [ ] 首页：一句话价值、选择文件/拖入按钮、运行合成示例、支持格式/限额、简短本地处理声明、非匿名保证提示；不铺满宣传卡片。
- [ ] 配置区：会场/年份/赛道、原文政策链接、规则能力说明；“我自己的身份词”折叠在可选区，旁边明确“仅本次会话”。
- [ ] 文件区：主稿与补充文件清楚分组；更换、移除、开始检查；同名文件用编号区分，不依赖把完整私人路径显示给用户。
- [ ] 空态：给一份故意有泄露的合成 PDF 和一份修正稿；无需登录和真实稿件也能体验。
- [ ] 校验态：超限/不支持类型/空文件立即就地提示；不支持的文件不能用灰色空结果隐藏。
- [ ] 解析态：显示当前文件、第 n/m 页、抽取/检测阶段、可取消；页面可操作，不用不可退出的全屏 spinner。
- [ ] 结果概览：高优先级 n、需核实 n、信息 n、解析覆盖页数；另列“未检查能力/页面”，不用巨大的绿色“安全”。
- [ ] 结果工作台：桌面双区布局为发现列表与 PDF；窄屏切换“发现 / 原页”，不把 PDF 挤成不可读缩略图。
- [ ] FindingCard：优先级文字、规则名、主稿/补充文件名、页码、原句、原因、建议、政策来源、置信度、复核状态；证据文字可复制。
- [ ] PDF 视图：上一/下一页、页码输入、缩放、旋转、当前命中框、多个命中跳转；无 bbox 时回退整页/原文而非画错位置。
- [ ] 筛选：文档、优先级、类别、复核状态；排序默认为优先级→文件→页码。筛选无结果时给清除筛选按钮，不误说稿件没有问题。
- [ ] 细节面板：显示链接真实目标、metadata 的字段名和值、tex 的路径行号；只有与这一发现相关的信息，避免大段原稿无必要铺开。
- [ ] 异常态：坏 PDF、密码保护、worker 起不来、字体丢失、扫描版、单页抽取失败、用户取消；每项都有不上传的下一步建议。
- [ ] 重新检查：清晰选择“同稿重跑 / 换修正稿”；若新稿变了，旧复核状态不自动判定新稿已修复；P1 可做稳定标识对比但只称差异。
- [ ] 帮助/能力页：规则解释、政策来源、隐私实现、未覆盖项、报告含敏感信息提醒、如何回源码修复；不建立需要登录的后台。



## 13｜隐私承诺要被实现和测试支撑

> **建议产品文案** （info）“论文文件在当前浏览器中分析，应用不会上传文件或正文，也不调用云端 AI。默认不保存稿件；清空后可重新开始。结果只是提示，扫描页、图片内容和外部网站仍需人工复核。”托管平台的访问日志/基础统计需另列说明，不能承诺网站绝对零网络记录。


- [ ] 应用源码不建立上传接口，不使用 FormData 传文件，不把 PDF/文本/姓名传给 fetch/XHR/WebSocket/sendBeacon、分析 SDK、错误监控或 Qoder Cloud Agents。
- [ ] 自定义词、文档文本、文件名和报告默认只在内存。localStorage 仅可存语言/主题/通用预设等非稿件偏好；IndexedDB 不存稿件。
- [ ] 清空操作：终止任务、destroy PDF loading task、释放文本/页缓存、清理 object URL、清空自定义身份词与决策。说明这是释放应用引用，不是浏览器内存取证级安全擦除。
- [ ] 不引入第三方广告/聊天插件/埋点/远程字体；所有运行依赖同源。平台自带脚本单独检查，无法控制的访问统计写入隐私说明。
- [ ] Network 验证不仅 monkey-patch fetch：用浏览器网络日志/Playwright 捕获请求，检查 XHR、beacon、图片、字体、导航；用合成带唯一 canary 字符串的稿件检查请求 URL/请求体。
- [ ] 区分初次加载静态资源、worker/字体的按需加载和文档内容上传；“处理不上传”不等于第一次打开网页完全不联网。
- [ ] 渲染 snippet/metadata/文件名一律纯文本转义，不使用未经清洗的 innerHTML；报告 HTML 同样转义，测试 </script>、引号、恶意标签和双向控制字符。
- [ ] 禁止执行 PDF JavaScript、表单动作、Launch action、TeX 命令和 ZIP 内容；不使用完整交互 PDF viewer 执行外部 action。内嵌网页附件不自动显示。
- [ ] 只为用户主动打开的外链允许 http(s)，不给 javascript:/data:/file: 可点击执行入口；默认报告链接文字不预加载、不生成远程预览图。
- [ ] CSP 在平台允许时限制 connect-src、object-src、base-uri 等，worker-src 与实际打包方式匹配；平台 header 可配置性未实测，不能把 CSP 当唯一安全层。
- [ ] 做资源上限与超时，worker 是可终止的计算线程不是 OS 沙箱；维持 pdf.js 安全更新与依赖审查，不能将“本地”写成“任何恶意 PDF 都安全”。
- [ ] 开发期间也不得把真实未发表论文放到 Qoder 提示、Repo Wiki、代码仓库、issue 或演示视频；开发 AI 接触合成数据不等于运行时 AI 读论文。
- [ ] 下载报告前提示可能包含作者身份和论文原句；默认提供隐藏文件名/脱敏片段选项，用户确认后才导出完整证据。



## 14｜.tex 与 ZIP：可选，但安全边界具体

- [ ] P1 先支持单个 .tex，UTF-8 解码并可提示编码异常，限制单文件 2 MB；保留原始行号。可选 .bib 仅作引用上下文，不做所有人名报错。
- [ ] ZIP 导入必须显式标注“源码包，不会编译”；列出处理/跳过的文件，默认只允许 .tex/.bib/.md/.txt 与少数原始图像格式。
- [ ] 初始 ZIP 产品限制建议：压缩包 10 MB、文件数 200、单条解压后 5 MB、总解压后 30 MB、路径深度 8、无嵌套压缩包；这些数字是待实测设计参数，不是 JSZip 自动保证。
- [ ] 预读 ZIP central directory 检查宣称体积/条目数/压缩比只是第一层，不可信；若库不能限制实际流式解压字节，不能靠声明大小防 bomb。
- [ ] JSZip 的完整解压可能先占用大量内存：放 worker+超时仍不能彻底防止 OOM。若没有足够测试和可中断字节限额方案，三周正式版禁用 ZIP，只接受 .tex 或手工挑选文件。
- [ ] 路径规范化拒绝 ../、绝对路径、驱动器路径、NUL、重复/冲突项；即使不落磁盘，也防止文件树与报告路径误导。
- [ ] 不递归解析嵌套 ZIP，不执行 .sty/.cls/.py/.sh，不跟随 include 的外部路径/URL；本地包里未提供的 include 文件报告缺失。
- [ ] 注释中的姓名与有效命令中的姓名分开标：源码本身泄露与 PDF 可见泄露不是一回事；带匿名 review 模式仍有有效 \author 不能直接判 PDF 违规。
- [ ] 源代码/README/LICENSE 里的版权姓名有真实合规含义；建议复制匿名审稿制品而非永久删原仓库版权，不篡改许可证。
- [ ] P2 图像元数据只对可直接读取的原始图片运行；不支持 video 音轨识别、不识别手写签名、不承诺截图水印扫描。

## 16｜测试语料：全部合成，带金标可复现

- [ ] 绝不用真实未发表论文或收到的评审稿作夹具；模板按许可使用，示例正文和身份均虚构，邮箱统一 example.org 等保留域。
- [ ] 从通用两栏 LaTeX 合成模板生成两套：有意泄露稿和修正稿；同时覆盖英文与中文 XeLaTeX 文本；模板来源和许可证记录在 fixtures/README。
- [ ] 建立至少 48 份小型文档：18 个单规则阳性、12 个合法负例、10 个混合/跨页/跨栏案例、8 个格式异常/资源边界案例；各类别可复用模板但金标独立。
- [ ] 直接身份例：Info.Author=XMP 不一致、邮箱仅在链接目标、页眉姓名、致谢人名、grant 编号、个人 GitHub/HF 链接、supplement 文件名。
- [ ] 引用负例：第三人称作者姓名、他人机构、pytorch 公共仓库、arXiv 文献、正常 our method、无资助语境数字、AI-use-only 致谢、Anonymous Authors。
- [ ] 解析边界例：fi/fl 连字、软连字符、跨行邮箱、两栏阅读顺序、旋转页面、英文缩写、中文无空格、缺 ToUnicode、图片扫描页、混合文本/扫描页。
- [ ] 结构残留例：PDF annotation 作者、内部页跳转与外部链接、嵌入附件名、可见 Code 与实名目标不同、不同类型 metadata；不能用 raw 正则修改 PDF 二进制造损坏夹具。
- [ ] 异常例：空文件、损坏 PDF、加密 PDF、超页数、体积边界、worker 失败、取消后旧回调、恶意显示字符串、超长文本项；ZIP 打开前另准备 bomb 风险可控的边界测试，不制作失控资源样本。
- [ ] 每份 golden 存 manifest：expectedRuleIds、source、page、原始证据文本、允许 bbox 误差、预设差异、expectedCoverage、expectedNotFindings；金标由人独立确认。
- [ ] 合成 PDF 在本地可信编译环境生成，不在产品里执行用户 TeX；固定引擎/模板版本与随机种子，保存可复现命令和夹具校验值。
- [ ] 公开演示只用合成 sample-leaky.pdf、sample-fixed.pdf、sample-supplement.pdf；文中明确标注“虚构投稿稿件”，不伪造真实拒稿故事。
- [ ] 如采用外部公开已发表论文仅用于兼容性阅读，先确认授权与用途；不把其作者信息当真实违规案例展示，不发布带真实个人数据的截图。



## 17｜单测、集成、端到端与质量指标

- [ ] 每个 P0 规则至少 3 个阳性+3 个负例+1 个 Unicode/边界例；测大小写、换行、标点、空值、匿名占位和参考区差异。
- [ ] 正则全局标志的 lastIndex 不能跨文档残留；转义用户词条，输入 .*、[]、反斜杠不会改变规则。限制候选文本长度，避免灾难回溯。
- [ ] 规范化单测：原→规范化→命中回映射；连字一对多、去断行、零宽字符与多 bbox 必须能恢复原句。
- [ ] 布局单测：单栏/双栏/标题跨栏、页眉重复、参考区边界；无法判断布局不丢失直接邮箱/姓名命中。
- [ ] 元数据单测：Info 有 XMP 无、反之、两者冲突、Author=Anonymous、Title 正常、Creator 通用、无字段、字段包含 HTML。
- [ ] 链接单测：visible label 与 target 不同、mailto、DOI、第三方库、实名本稿仓库、Hugging Face datasets/spaces、多级 GitLab、内部 dest、javascript:/file: 只显示不执行。
- [ ] 预设单测：同一稿 ARR 的 AI-only 致谢不等于资助致谢；CVPR 合法引用外链与扩展内容分开；MobiCom 的歧义提示始终可见；不支持预设不显示“完整通过”。
- [ ] 状态单测：导入 A 后立刻导入 B，A 旧结果不能落入 B；点击取消、卸载组件、连续重跑、导出同时换稿均不崩。
- [ ] 报告测试：JSON schema 校验、中文字符、换页、脱敏选项、忽略项数量、未扫描页、空发现；不含原始 ArrayBuffer/全稿文本。
- [ ] E2E 1：打开站点→运行合成稿→至少一条直接身份发现→点击定位→看建议→导出→导入修正稿→发现减少且仍有人工复核说明。
- [ ] E2E 2：混合扫描页→显示 partial coverage→导出含未检查页；不能出现绿色全通过。
- [ ] E2E 3：使用 canary 合成身份词，捕获 network/navigation/存储/console，确认没有稿件衍生内容外传；后台托管请求单独归类并审查。
- [ ] E2E 4：Chromium/Firefox/WebKit 测公开站点可用；本地内存/下载限制导致不支持时准确显示降级，不通过 user-agent 硬假装支持。
- [ ] 指标按检测面拆开：直接身份规则 precision/recall，启发式规则 precision、每文档误报数、页码定位正确率、部分解析率；不把 metadata 行和文本行随便混成总准确率。
- [ ] 建议放行门槛：金标 P0 直接身份集合 recall=100%、precision≥95%，启发式 precision≥80% 或明确降为低置信；页码正确率100%、可定位证据框≥95%。这些是本合成集目标，不可宣传为真实世界准确率。
- [ ] 20% 合成变体在最后一周作保留集，不反复按测试集调阈值；小样本指标同时写样本数、失误例和适用范围。
- [ ] CI 静态检查不代表隐私保证：仍需人工读解析/网络/导出代码、正式站点检查和文案核对；最终在 docs/qa-report.md 记录未解决问题。



## 18｜可访问性、响应式与性能

- [ ] 所有操作键盘可达：文件选择、开始/取消、筛选、结果跳转、翻页、缩放、导出；拖拽不是唯一入口。
- [ ] 优先级用文字+图形/标识，不只红黄绿；正文与背景对比度按 WCAG AA 目标检查，深浅色均测试。
- [ ] 进度 aria-live=polite，解析错误 role=alert；不要每一页进度都抢读屏。新结果可聚焦总标题，用户主动选发现后焦点有可预测去向。
- [ ] PDF canvas 本身不可读屏，另提供语义化 Finding 列表和原文片段；高亮证据有文本等价信息。
- [ ] 360px 窄屏与 200% 缩放：按钮换行、筛选可折叠、长 URL 可断行、报告不卡横向，预览允许合理缩放/滚动。
- [ ] 点击目标足够大，loading/disabled 状态清楚；支持 prefers-reduced-motion，无自动滚动动画妨碍定位。
